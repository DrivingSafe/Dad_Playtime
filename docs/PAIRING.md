# 엄마·아빠 연결(매칭) 설계

현재(v0.9)는 서버가 없어서 한 기기 안에서만 엄마/아빠 역할을 나눈다. 두 사람이 각자 폰에서 같은 기록을 보려면 서버(Firebase)가 필요하다.

## 핵심 개념
- **가족(family)** 하나가 아이 1명의 기록을 가진다. 엄마·아빠는 같은 가족의 **구성원(member)** 이고, 각자 역할(`dad`/`mom`)을 가진다.
- 누가 먼저 시작해도 같다: 먼저 시작한 사람이 가족을 만들고 **초대 코드(링크)** 를 받아 상대에게 보낸다. 상대는 코드로 합류한다.

## 흐름
| 단계 | 첫 번째 사람 | 두 번째 사람 |
|---|---|---|
| 1 | 앱 열기 → 익명 로그인(자동) | |
| 2 | 아이 정보 입력, 역할 선택(아빠/엄마) → 가족 생성 | |
| 3 | 초대 링크 `…/?join=K7P4QX` 와 6자리 코드 표시, 카카오톡·복사로 전달 | |
| 4 | | 링크를 열면 앱이 코드 확인 → 익명 로그인(자동) |
| 5 | | 남은 역할이 자동 선택됨(첫 번째가 아빠면 엄마). 같은 역할이면 "이미 아빠가 있어요" 안내 |
| 6 | 서로 연결 완료: 같은 기록, 서로의 메시지·지시가 실시간 반영 | |

## 데이터 구조 (Firestore)
```
users/{uid}                  { familyId, role, nick }
families/{fid}               { createdBy, createdAt, childAlias, birthYM, sex }
families/{fid}/members/{uid} { role, joinedAt }
families/{fid}/ms|plays|body|msgs|conf|fb|errands|memo|shelf/...   (지금 앱의 컬렉션과 같은 모양, 가족 아래로 이동)
invites/{code}               { familyId, role(남은 역할), expiresAt, usedBy }
```

## 보안 규칙 요점
- `families/{fid}/**` 는 `members/{auth.uid}` 문서가 있는 사람만 읽기·쓰기.
- 초대 문서는 코드를 정확히 알 때만 읽을 수 있다(`get`만 허용, `list` 금지).
- 합류: 로그인한 사용자가 `members/{자기 uid}` 를 만들 수 있는 조건 = 유효한 초대(만료 전, 미사용)가 있고 역할이 남은 역할과 같을 때. 초대는 합류와 같은 배치에서 `usedBy` 로 닫는다.
- 구성원은 최대 2명(엄마·아빠). 할머니 등 추가 보호자는 이후 단계.

## 반드시 같이 만들 것
- **계정 복구**: 익명 로그인은 브라우저 데이터를 지우면 접근을 잃는다 → 구글/이메일 연결 옵션 또는 가족 복구 코드.
- **연결 해제·나가기**, 아이 기록 삭제(탈퇴 시 가족 데이터 삭제).
- 동의 화면(건강정보 별도 동의), 처리방침.

## 지금 앱에서 확인하는 방법
`?dev=1` 개발자 모드의 **보기 역할**(전체/아빠/엄마)로 역할별 탭·화면을 미리 볼 수 있다. 실제 두 기기 연결은 위 서버 작업 이후.

## 만드는 순서
1. Firebase 프로젝트(Auth 익명, Firestore 서울 리전) 생성 — 사용자
2. Firebase 어댑터(`getBackend`에 같은 모양으로 추가) — 개발
3. 가족 생성·초대·합류 화면, 보안 규칙, 에뮬레이터 테스트 — 개발
4. 계정 복구, 동의 화면, 탈퇴 — 개발

## 보고 알림 (엄마 폰)
- 아빠가 "엄마에게 보고하기"를 누르면 `families/{fid}/msgs`에 보고 문서가 생기고, 서버 함수(Cloud Functions)가 엄마 기기의 푸시 토큰(FCM)으로 알림을 보낸다. 푸시 토큰은 `users/{uid}`에 저장. 서버 함수는 유료 플랜(Blaze) 필요.
- iOS 웹앱 푸시는 홈 화면에 설치한 PWA에서만 동작한다.
